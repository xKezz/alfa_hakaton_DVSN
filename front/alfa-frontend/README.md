# alfa-hakaton-DVSN — frontend (React + Vite)

Прототип клиентского и банковского интерфейса кредитного конвейера для ИП и ООО.
Сделан на **React 19 + Vite 8** без дополнительных UI-библиотек: только React,
CSS и собственные переиспользуемые компоненты.

## Экраны

| Экран | Где | Что делает |
|---|---|---|
| Вход | `src/pages/LoginPage.jsx` | Авторизация предпринимателя/сотрудника через API, ошибки, загрузка |
| Кабинет предпринимателя | `src/pages/EntrepreneurDashboard.jsx` | Заявки из API по ИНН клиента, поиск и фильтры, статусы, переход в карточку |
| Подбор кредита | `src/pages/CreditCalculator.jsx` | Активные продукты из `loan_catalog` через API; форма заявки с кнопкой «Заполнить из профиля»; отправка заявки через `POST /api/loan-applications` с реальным скорингом и статусом |
| Профиль компании | `src/pages/ProfilePage.jsx` | Данные предпринимателя и бизнеса (localStorage), проверка компании по ИНН через API, годовая финансовая отчётность: существующие годы загружаются из БД только для чтения, за новый год можно добавить |
| Карточка заявки клиента | `src/pages/ApplicationDetails.jsx` | Статус и история из API, скоринг, альтернативные предложения из `application_offers`, выбор/отказ от оффера |
| Интерфейс сотрудника банка | `src/pages/BankWorkspace.jsx` | Очередь `manual_review` из API, вкладки «Компания / Финансы / Проверки / Скоринг / История», решение через `POST /api/loan-applications/{id}/decision` |
| История | компонент `Timeline` в `src/components/ui.jsx` | Вертикальный таймлайн событий |

Общие компоненты (кнопки, поля, бейджи, табы, модалка, тост, gauge) — `src/components/ui.jsx`.
Дизайн-токены и базовые стили — `src/index.css`, стили экранов — `src/App.css`.
Демо-данные — `src/data/mock.js`. Клиент API — `src/api.js`.

## Запуск

```bash
cd front/alfa-frontend
npm install          # при первом запуске
npm run dev          # http://localhost:5173
```

Сборка и проверки:

```bash
npm run build        # production-сборка в dist/
npm run lint         # oxlint
npm run preview      # предпросмотр собранной версии
```

## Локальные учётные записи

Создаются скриптом `DB/setup_db.py` и проверяются backend'ом через БД:

| Логин | Пароль | Роль |
|---|---|---|
| `client` | `client` | предприниматель |
| `bank` | `bank` | сотрудник банка |
| `login1` | `login1` | предприниматель |

Перед запуском скопируйте `backend/.env.example` в `backend/.env` — там уже
указаны рабочие локальные параметры PostgreSQL и dev-значение `AUTH_SECRET`.

## Подключение к backend

По умолчанию frontend обращается к `http://localhost:8000`. Адрес можно
переопределить переменной окружения:

```bash
cp .env.example .env
# при необходимости измените VITE_API_URL
```

Backend (FastAPI + PostgreSQL) находится в `../backend/`, там же инструкция по
настройке `.env` и применению `DB.sql`. Доступные эндпоинты:

- `GET /health` — статус сервиса и базы данных;
- `GET /api/companies/{inn}` — компания по ИНН из таблицы `companies`;
- `POST /api/financial-statements` — сохранение годовой финансовой отчётности в таблицу `financial_statements`;
- `GET /api/loan-products` — подбор активных продуктов из таблицы `loan_catalog` по параметрам.

Если backend недоступен, интерфейс продолжает работать на демо-данных:
в шапке/футере показывается «API недоступен · демо-данные», а в форме заявки и
профиле доступна кнопка получения демо-сведений о компании.

## Ограничения прототипа

- Авторизация и все финансовые решения — демонстрационные, без реального API банка.
- Заявки, продукты, ставки, скоринг и решения хранятся в mock-данных и
  `localStorage` (создание заявки, принятие предложения, решения сотрудника).
- Backend реализует только health-check и получение компании по ИНН; бизнес-логики
  кредитования, аутентификации и загрузки документов пока нет.
- Все суммы, ставки и условия не являются офертой банка.
